# Synthetic examples only

All domains, quantities and receipts here are illustrative. `read-only-plan.json` can be validated offline; `synthetic-*-receipt.json` files demonstrate local state, not actual Koala observations. Never submit synthetic receipts as proof of live execution.

`standalone-draft-plan.json` demonstrates a structurally valid standalone generation phase, not an approved action. It intentionally omits brandId/projectId and sets real generation options instead of a fictional publish switch. The 6,000-word reservation is an illustrative local allowance, not a predicted bill or a claim about the user’s plan. Review actual effective settings, entitlement, authority and word consumption before any real call. No approval file is bundled.

A production phase with a dynamically returned articleId needs a new immutable read plan containing that actual ID; do not put placeholders into live tool calls. Keep private plans, approval files and receipts outside this directory.
